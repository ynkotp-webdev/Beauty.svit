# Beauty Svit — редизайн

Салон краси, вул. Сихівська 7, Львів. Сегмент A-mass з преміальною лінією всередині прайса.
Зроблено скілом `beauty-redesign` (гілка `generate`), Astro 7 + Tailwind 4, статика.

```bash
npm install
npm run prep     # webp з оригіналів клієнта + src/data/*.json з вигрузки Appointer
npm run build
npm run preview  # http://localhost:4321
```

Аудит гнати **по production-збірці** (`build` + `preview`), не по `dev`.

## Що змінилось по суті

**Ціни з'явились на сайті.** Раніше не було жодної цифри: прайс жив лише всередині віджета
Appointer. Перенесено 107 позицій із ціною, хронометражем, складом послуги й іменем виконавця,
плюс власні пояснення салону («фарба завжди включена у вартість», «густе волосся +10%»).

**Шкала довжин 1–5 стала опорою сторінки.** Салон уже рахує ціну за власною шкалою, але ніде її
не показував. Тепер вона на першому екрані, у прайсі й на кожній сторінці послуги, де ціна від
неї залежить.

**Градація майстрів названа.** «Виконує ТОП-майстер» лежало в описах CRM. У прайсі це розворот:
базова ціна проти ціни ТОП-майстра, з іменем. Пари виводяться з самих даних, а не призначаються
руками, — там, де різниці немає, сторінка про градацію мовчить.

**Чужі фото прибрані повністю.** З 90 зображень старого сайту приблизно половина — роботи з
Pinterest та чужих акаунтів (`Top-28-Medium-Curly-Hairstyles-…divagaze_com`, `@manikure_belgorod`).
Не перенесено жодного. На сайті лише 15 власних кадрів із залу та 3 знімки інструмента.

**Структура пересобрана.** Було 16 пунктів меню й 60 URL при одній сторінці на всі послуги.
Стало 5 пунктів, 11 сторінок послуг, окрема сторінка прайса, робіт, майстрів і локації.

**Платформа запису збережена.** Appointer вбудований модально й обрамлений токенами сайту.
Оферта й політика конфіденційності перенесені посиланнями. Усі 12 відгуків — із посиланнями на
профілі авторів у Google Картах, плюс друга площадка barb.ua.

## Що потрібно від власника

Без цього сайт працює, але ці місця залишаються слабкими.

1. **Фото майстрів.** У CRM замість портретів стоять мальовані коти. Зараз картка майстра
   тримається на імені, спеціалізації, кількості відгуків і його роботах. Потрібна репортажна
   зйомка п'ятьох людей в однакових умовах.
2. **Широкий кадр залу і вивіски.** Усі 15 власних знімків вертикальні, максимум 1280px по
   ширині. Через це перший екран зроблено віялом смуг, а не повношириною фотографією.
3. **Протоколи стерилізації.** Даних немає жодних. Писати загальними словами не стали. Потрібно:
   чим обробляється інструмент, у чому пакується, що одноразове. Це закриє `TRUST-004` і одну
   з найсильніших претензій ніші.
4. **Рішення по передоплаті.** monobank у Appointer підключений, дисклеймер про 24 години
   написаний, але `widgetShowDeposit: false`. Вмикати чи ні.
5. **Аналітика.** У віджета своя властивість GA (`G-ZB0366JLB4`). Ставити той самий тег на сайт
   чи заводити окрему властивість — рішення власника; мовчки не додавали. Закриє `BOOK-010`.
6. **Підтвердити цифри зі сторінки «Про нас»**: 3 роки, 2894 візити за рік, 7 спеціалістів.
   Зараз стоять як заява власника. Якщо не підтверджуються — знімаємо.
7. **Шість майстрів у CRM без імен** (числові id 22842, 23151, 25822, 26361, 28558, 22132).
   Вони виконують позиції прайса, але в картках їх немає.
8. **Опечатка в CRM:** «Вихід із чорного, 3 довжина» стоїть 241 хв замість 240. У рядку прайса
   значення показане як є; у діапазонах округлюється до 5 хв.
9. **Заточка інструмента** є на старому сайті й у нас у фото, але її немає в прайсі Appointer.
   Потрібні ціни, інакше послугу не можна ані показати, ані забронювати.
10. **Згода на обробку персональних даних.** Своєї форми на сайті немає, дані збирає Appointer.
    Варто перевірити з юристом, що чекбокс і політика показані всередині віджета.

## Що лишилось у звіті і чому

8 порушень. Жодне з них не чиниться версткою.

| Правило | Статус |
|---|---|
| `TRUST-004` стерилізація | **немає даних** — пункт 3 списку вище |
| `BOOK-010` аналітика | **рішення власника** — пункт 5 |
| `LEGAL-001` чекбокс згоди | **баг правила**: форми на сайті немає, але пропуск «форми немає» спрацьовує лише коли `BOOK-012` іде у skipped. Оскільки запис зовнішній, `BOOK-012` став порушенням і пропуск не відпрацював |
| `BOOK-023` термін відповіді | **баг правила**: та сама причина, форми заявки немає |
| `BOOK-005` кроки візарда | **баг правила**: шукає «Крок N з M» усередині чужого iframe, куди детектор не дістає |
| `BOOK-012` запис на зовнішньому домені | **свідомий вибір**: платформа клієнта зберігається, це записано в `PRODUCT.md` |
| `SEO-014` розмітка Review | **баг правила**: перевірка `element_exists` спрацьовує на сам факт наявності `AggregateRating` і не вміє перевірити видимість першоджерела. Рейтинг реальний (4.8/116), посилання на Google Карти стоїть у підвалі кожної сторінки |
| `SEO-009` URL | **баг правила**: регулярка `/(ua\|uk)/[a-z-]+/[a-z-]+/` вимагає мовний префікс. Сайт одномовний, префікс `/uk/` був би фікцією заради правила |

Окремо: `screensToFirstPortfolioImage` зріс з 1.93 до 6.24 — детектор рахує мозаїку робіт унизу
сторінки й не зараховує віяло першого екрана, хоча в ньому теж реальні роботи салону.

## Викладка

Статика, `dist/` кладеться як є. Для прев'ю на GitHub Pages:

```bash
BASE=/Beauty.svit npm run build
```

`base` читається в [astro.config.mjs](astro.config.mjs); усі посилання й ассети з `public/`
йдуть через хелпер `u()` з [src/lib/site.ts](src/lib/site.ts), інакше вони ламаються на підшляху.
`/sitemap.xml` — власний ендпоінт, а не `@astrojs/sitemap`: інтеграція кладе `sitemap-index.xml`,
якого детектор і пошуковики не питають.
